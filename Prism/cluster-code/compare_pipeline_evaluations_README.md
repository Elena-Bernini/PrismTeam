# Retrieval Pipeline Evaluation Comparison

This module compares multiple retrieval evaluation outputs produced after the preprocessing and retrieval stages.

It is intended to be used after running:

1. `preprocessing.py`
2. `retrieval_pipelines.py`
3. `evaluate_retrieval.py`

The script reads one or more evaluation folders and creates a unified comparison of the retrieval pipelines.

Typical use case:

- compare the graph pipeline against a ResNet50 vision pipeline;
- compare ResNet50 against DINOv2;
- summarize all architectural retrieval metrics in one table;
- generate plots that can be used in reports or presentations.

---

## Input Requirements

Each evaluation folder must contain the files generated by `evaluate_retrieval.py`, especially:

```text
metrics_per_result.csv
```

A typical project structure is:

```text
Prism/
├── cluster-code/
│   ├── preprocessing.py
│   ├── retrieval_pipelines.py
│   ├── evaluate_retrieval.py
│   └── compare_pipeline_evaluations.py
├── data/
│   └── processed/
│       └── rplan/
└── outputs/
    ├── evaluation_resnet50/
    └── evaluation_dinov2/
```

## Evaluation Labels

Each `--evaluation` argument can optionally include a label:

```text
path/to/evaluation:label
```

Examples:

```text
outputs/evaluation_resnet50:resnet50
outputs/evaluation_dinov2:dinov2
outputs/evaluation_vit:vit
```

The label is used only for display and report generation.

## Metrics Compared

The script compares the metrics generated by `evaluate_retrieval.py`, including:

- architectural score;
- room-type similarity;
- room-count similarity;
- area similarity;
- adjacency similarity;
- relation similarity;
- grid-location similarity;
- constraint score;
- hard-constraint satisfaction;
- FAISS/vector similarity.

The FAISS similarity is useful for debugging the vector index, but it should not be interpreted as architectural quality by itself.

---

## Interpretation

The comparison is designed to answer questions such as:

- Does the graph pipeline retrieve layouts with more similar room composition?
- Does the vision pipeline retrieve visually similar but semantically different layouts?
- Does DINOv2 improve over ResNet50?
- Is the graph representation still stronger for architectural constraints?
- Does retrieval quality degrade with rank?

A strong graph pipeline is expected to perform well on semantic and topological metrics, while a vision pipeline may perform better on visual similarity but weaker on room-level architectural constraints.
