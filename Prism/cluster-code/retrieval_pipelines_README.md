# RPLAN Post-Preprocessing Retrieval Pipelines

This module runs the retrieval stage after the RPLAN / Graph2Plan preprocessing step.
It consumes the preprocessed layout and graph JSON files and builds two retrieval pipelines:

1. **Graph retrieval pipeline**
   - Input: `graphs_json/*.json` and `layouts_json/*.json`
   - Encoder: interpretable structural graph descriptor
   - Retrieval backend: vector similarity index
   - Output: ranked nearest-neighbor floorplans, JSON results, and PNG grids

2. **Vision retrieval pipeline**
   - Input: rendered floorplan snapshots from `snapshot_train/*.png`
   - Encoder: image backbone such as `resnet50`, `resnet18`, `dinov2_*`, `timm:<model>`, or CPU-only `colorhist`
   - CUDA support: Torch-based image encoders run on GPU when `--device cuda` or `--device auto` resolves to CUDA
   - Retrieval backend: vector similarity index
   - Output: ranked nearest-neighbor floorplans, JSON results, and PNG grids

The script is intentionally designed to be launched from the project root. The default paths assume this project structure:

```text
Prism/
├── cluster-code/
│   └── post_preprocessing_retrieval.py
├── data/
│   ├── raw/
│   │   └── rplan/
│   │       └── extracted/
│   └── processed/
│       └── rplan/
│           ├── layouts_json/
│           └── graphs_json/
└── outputs/
```

## Input requirements

Before running this script, preprocessing must have already generated:

```text
data/processed/rplan/layouts_json/*.json
data/processed/rplan/graphs_json/*.json
```

The vision pipeline also expects the rendered RPLAN snapshots:

```text
data/raw/rplan/extracted/Interface/static/Data/snapshot_train/*.png
```

Every image ID is matched against the preprocessed layout IDs, so the vision pipeline only uses snapshots that also have a corresponding `layout.json`.

## Clean old retrieval outputs

Do not delete the preprocessing output unless you intentionally want to rerun preprocessing. The following commands remove only retrieval artifacts and old retrieval reports.

### Windows PowerShell

```powershell
Remove-Item data\processed\rplan\retrieval\graph_faiss -Recurse -Force -ErrorAction SilentlyContinue
Remove-Item data\processed\rplan\retrieval\vision_faiss -Recurse -Force -ErrorAction SilentlyContinue

Remove-Item outputs\retrieval_cpu_full -Recurse -Force -ErrorAction SilentlyContinue
Remove-Item outputs\retrieval_gpu_test -Recurse -Force -ErrorAction SilentlyContinue
Remove-Item outputs\retrieval_gpu_full -Recurse -Force -ErrorAction SilentlyContinue
Remove-Item outputs\retrieval -Recurse -Force -ErrorAction SilentlyContinue
```

### Linux / cluster shell

```bash
rm -rf data/processed/rplan/retrieval/graph_faiss
rm -rf data/processed/rplan/retrieval/vision_faiss
rm -rf data/processed/rplan/retrieval/graph_pipeline
```

## Smoke test with CUDA

Run a small test before processing the full dataset. This builds both pipelines on the first 1000 items and creates three random query examples.

```powershell
python .\cluster-code\post_preprocessing_retrieval.py `
  --pipeline both `
  --build `
  --clean `
  --processed-root data\processed\rplan `
  --outputs-root outputs\retrieval_gpu_test `
  --max-items 1000 `
  --vision-backbone resnet50 `
  --vision-weights imagenet `
  --device cuda `
  --batch-size 16 `
  --random-queries 3 `
  --top-k 10
```

If GPU memory is limited, use one of these adjustments:

```powershell
--batch-size 8
```

or:

```powershell
--vision-backbone resnet18
```

If you want the script to automatically use CUDA when available and CPU otherwise, use:

```powershell
--device auto
```

## Pipeline interpretation

### Graph retrieval

The graph pipeline retrieves layouts with similar structural and semantic properties. Its descriptor includes:

- number of rooms;
- number and density of graph edges;
- room type histograms using the official RPLAN / Graph2Plan room IDs;
- relation histograms using the official Graph2Plan relation IDs;
- room area statistics;
- centroid distribution;
- bounding-box shape statistics;
- graph degree statistics;
- external boundary descriptors.

This is an interpretable baseline before moving to trainable graph neural network embeddings.

### Vision retrieval

The vision pipeline retrieves layouts from rendered floorplan snapshots. With `resnet50` or `resnet18`, image features are extracted with a pretrained ImageNet backbone and can run on CUDA. These visual features capture rendered appearance, color distribution, room layout, and global visual structure.

Graph and vision retrieval are expected to produce different neighbors. That difference is useful: the project goal is to compare graph-based and vision-based representations for semantic architectural search.

## Recommended workflow

1. Run the preprocessing script.
2. Clean old retrieval outputs.
3. Run the 1000-item CUDA smoke test.
4. Inspect the graph, vision, and comparison PNG grids.
5. Run the full CUDA retrieval build.
6. Use the generated JSON and PNG outputs for qualitative analysis.
7. Move next to quantitative evaluation: room-type similarity, adjacency similarity, constraint satisfaction, and Recall@K.
